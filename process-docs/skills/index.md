# Skills Index

Skills files capture non-obvious patterns, workarounds, and correctness requirements discovered during development. Read these before working on related code.

## Available Skills

- **[codebase-layout.md](codebase-layout.md)**: Where everything lives and what each part is responsible for: the one-file-per-module layout under `src/` and what each module owns, including the `mount.rs` build-mounts module, the dependency direction between them, the fact that `skopeo` is called only from `loader.rs`, the CLI surface and its flags, the fixed section order of the emitted Containerfile and the contents of a self-contained build context, where the examples and process docs sit, and the structural surprises worth knowing before you open a file (what `implemented/` does and does not claim about a spec or plan, the big source files are mostly inline tests, and why `main.rs` stays dispatch-only).

- **[containerfile-layer-semantics.md](containerfile-layer-semantics.md)**: What actually keeps bytes out of an image: why `COPY` then `RUN rm -rf` doesn't work, why `RUN --mount=type=bind` does, the four cases for `from=` (context, registry image, named stage, or omitted to resolve against the build context), and verification that bind mounts work in OpenShift on-cluster builds.

- **[registry-verification.md](registry-verification.md)**: Proving fragment metadata changes against a real registry: why the tool's skopeo calls fail on a plain-HTTP local registry and how to scope the insecure setting to the test, which command actually exercises the annotation fast path, how to read whether it fired, how to mirror a published location to the local registry so regenerated docs carry real refs, why a stale local image silently shadows the published fragment and how to force a refresh, why the published fragment set is mixed-architecture, and why inline `python3 -c` must never be used to derive build arguments here — it fails silently and once shipped eight fragments with no annotations at all.

- **[ocl-build-environment.md](ocl-build-environment.md)**: The OpenShift on-cluster layering build environment: buildah as the builder, credential handling, Containerfile validation, the 4096-character cap, and why the user doesn't control the build context.

- **[image-mode-package-adaptation.md](image-mode-package-adaptation.md)**: Encoding an application's image-mode adjustments in a fragment: why `%post` is where packages hide their image-mode problems and why `rpm -q --scripts` is the only way to see them, why the application's own startup log is the authority on where it reads a path (grafana's bundled plugins are homepath-relative, so its RPM's own `%post` move breaks them and makes it re-download from the internet), why `bootc container lint`'s `var-tmpfiles` is two checks wanting two different fixes and prints the `tmpfiles.d` lines it wants, why `sysusers.d` matches on names rather than IDs, and why `rpm -V` is a free second opinion on what a `%post` relocated.

- **[testing-surfaces.md](testing-surfaces.md)**: Where tests live and what each surface can exercise: inline unit modules vs. the offline-only CLI tests, the generator's fragment helpers and how `resolved_digest` flips the emitted `--from=` form, the double-COPY surprise for mixed fragments, the injected-call pattern that makes registry-independent logic testable offline, the mutation-verification rule for ordering guards, and what is known-unpinnable (`list` provenance, hook script behavior).

- **[blob-carrying-fragments.md](blob-carrying-fragments.md)**: Fragments whose `hooks/` carries a large vendor binary: the fetch-script-plus-recorded-sha256 pattern that keeps the blob out of git, why the registry mirror trick fails for local-only fragments (the digest lookup ignores mirrors), how the podman machine runs out of disk and what actually reclaims it, why a base image's kernel NVR is frequently absent from its own repos and how to build a coherent base for testing, why a driver that "supports 6.12" still fails against RHEL 10's backport-heavy 6.12, the exact rhsm and ldconfig residue any dnf-running entrypoint leaves and why measuring it against a scaffold base misattributes it to the base, why a fragment must only remove build tooling it actually installed, and why `python3 -m zipfile` cannot replace `unzip`.

- **[documentation-authority.md](documentation-authority.md)**: Which doc file wins when they disagree: `README.md` is authoritative over `docs/fragment-format.md`, the POC-era spec and plan under `process-docs/` are historical rather than current reference, and a spec filed under `implemented/` claims only that its work shipped, not that it still matches the code.

- **[fragment-input-invariants.md](fragment-input-invariants.md)**: The two fragment-supplied values that flow into paths and where each is checked: the fragment-name grammar enforced once by `FragmentName::new` (take a `FragmentName`, not a `&str`, when you add a filesystem join), the canonical layer-path form returned by `validate_tar_entry` (match its return value, never `entry.path()`, and note the checks run on the raw path before normalization), and why `tar::Header::set_path` is not path-transparent so fixture tarballs must write header names verbatim.
